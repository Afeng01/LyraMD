文稿安全

把最近备份、异常恢复和本地保留策略放到同一个入口，减少崩溃或误操作后的损失。

本地备份目录
本地备份与恢复怎么找
  1. 打开任意草稿或正式 Markdown 文稿后，点击标题栏的“文稿安全”按钮，即可展开当前文稿的本地历史。
  2. 列表会显示自动保存、手动保存、重命名、插图前检查点和异常恢复点；点“恢复为草稿”会新建一份草稿，不覆盖当前文稿。
  3. 最近备份会优先显示这一版相对上一版的具体修改摘要，而不是从头把整篇文稿重新展开。
  4. 如果上次是异常退出，右上方还会额外出现“异常恢复”提示；点“恢复为新草稿”即可把崩溃前最后一次快照找回来。
  5. 这里的保留条数只影响每篇文稿单独保留多少个本地版本，不会动你的正式 Markdown 文件。

Agent 协作

外部更新提示会显示新增、删除和修改行数；展开后可以查看摘要，并用“撤回这次更新”回到本轮外部更新之前。

和 Agent 一起改文稿时
  1. 外部更新提示会显示新增、删除和修改行数，方便先判断这次改动的量级。
  2. 如果这次更新不对，直接点“撤回这次更新”，会回到这轮外部写入之前。
  3. 如果要找更早的版本，再去“文稿安全”里从最近备份恢复成新草稿。

AI 精灵 Prompt

这些模板会用于选中文本后的 AI 精灵操作。使用 {{selection}} 表示当前选区；你也可以新增自己的精灵标题和 prompt。

AI 精灵怎么用
  1. OpenAI 官方账号：Base URL 保持 https://api.openai.com/v1，填入 API Key 和模型名。
  2. cpa/new-api：把 Base URL 换成你的网关地址，Model 填网关里可用的模型。
  3. 在正文里选中文本后按 Cmd/Ctrl+J 打开 AI 精灵，选择模板或输入指令；结果会以内联建议出现，可接受或拒绝。

Codex MCP 如何使用
  1. 在这里安装后，保持 LyraMD 打开当前文档。
  2. 在 Codex 里请求它使用 LyraMD MCP 读取或写入当前文档。
  3. LyraMD 负责安装配置和运行本地 bridge；Codex 负责真正调用 MCP 工具。

LyraMD 使用指南

这里是当前集成的实际使用方式，避免把 MCP、终端和草稿逻辑混在一起。

  1. 在 LyraMD 中写笔记，保持当前文档打开；未保存的新内容会先进入草稿。
  2. 需要正式落盘时，用保存或工作目录里的新建按钮，把文件放进对应文件夹。
  3. 终端里和 Alice 或 Codex 讨论内容时，让它通过已配置的本地连接读取当前文档，或直接把文件路径发给它。

更新日志

这里记录最近几个 LyraMD 1.x 版本的主要变化；更早的细节仍以 GitHub Releases 和提交记录为准。

LyraMD 1.3.7 当前公开版本
  • 继续打磨设置窗口、窗口状态和右上角活动提示，让多窗口状态更稳定。
  • 把 frontmatter 显示为可折叠的前置元数据卡片，同时保持 Markdown 原文和保存结果不变。
  • 补上设置里的更新日志入口，方便在应用内回看 LyraMD 1.x 的发布变化。
  • 增强未签名 macOS 构建的手动更新 fallback，检查到新版本后打开下载入口由用户覆盖安装。
LyraMD 1.3.6 更新通道
  • 加入应用内检查更新入口，macOS 未签名构建会打开最新 DMG 或 Release 页面进行手动覆盖安装。
  • 发布流程补齐 Windows x64 安装包、更新元数据和 release workflow 校验。
  • 发布检查清单新增 cold-start smoke、Milkdown 依赖一致性和 artifact 核对要求。
LyraMD 1.3.5 启动修复
  • 修复 1.3.0 包体启动后编辑器不可用的问题，统一 Milkdown core 依赖入口。
  • 增加 Milkdown 依赖回归测试，避免再次混用不同 core 注入链。
  • 补充项目内历史恢复和发布事故 checkpoint，方便后续接手排查。
LyraMD 1.3.0 交互打磨
  • 回到 LyraMD 1.x / Electron + Milkdown 基线，明确 Cmd/Ctrl+J 打开 AI 精灵。
  • 打磨侧边栏、工作目录、AI 精灵和 provider presets，保留轻量写作工作台方向。
  • 加入反馈与问题入口，可生成预填 GitHub Issue，不在本地保存 GitHub token。
LyraMD 1.2.1 Workbench polish
  • 整理 README 徽章、下载入口和平台说明，让 macOS 稳定版与 Windows 预览版边界更清楚。
  • 补充 Windows 预览安装路径，说明 x64 安装包仍需要真实设备 smoke testing。
  • 继续打磨工作台侧边栏、窗口菜单和渲染层状态，减少工作目录与最近文件的状态漂移。
LyraMD 1.2.0 协作底座
  • 加入外部 Agent 更新摘要、批量合并提示和一键撤回，让外部写入当前 Markdown 时更可控。
  • 补齐工作目录 tab、稳定的工作区顺序、侧边栏删除/重命名确认和退出时工作区历史持久化。
  • 加入可自定义快捷键、确定性的中英排版清理、浮动文内搜索和标题/文件同步相关设置。
  • 拆分 macOS 正式发布与 Windows preview 构建，并开始准备 Windows 安装包与 smoke 脚本。
LyraMD 1.0.3 LyraMD 起点
  • 确定 LyraMD fork 的产品方向：保留 ColaMD 的 agent-native 单文件编辑核心，同时增加个人写作工作台导航。
  • 提供外部 Agent 修改当前 Markdown 后的实时刷新、Milkdown WYSIWYG 编辑和基础主题/导出能力。
  • 加入轻量侧边栏、当前文件、最近文件和持久工作目录，方便在少量 Markdown 文稿之间切换。
  • 明确 macOS 未 notarized 的安装说明和 LyraMD / ColaMD 命名归属。
版本边界 说明
  • LyraMD 没有单独发布 1.1.x 公开 tag；那段搜索、设置、工作区、Windows preview 等变化集中进入 1.2.0。
  • 本页只记录 Afeng01/LyraMD 的发布线；本地存在的 ColaMD 上游 tag 不计入 LyraMD 更新日志。
