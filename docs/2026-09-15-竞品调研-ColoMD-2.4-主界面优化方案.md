# ColaMD 2.4 竞品调研与主界面优化方案（2026-09-15）

此文件帮助 agent 与她回答三个问题：ColaMD 1.9 之后到 2.4 更新了什么、我们的主界面（标签页 / 侧边栏）按什么方案优化、竞品里哪些功能值得抄以及按什么顺序抄。调研由子 agent 于 2026-09-15 完成，来源为 [ColaMD Releases](https://github.com/marswaveai/ColaMD/releases)、[README roadmap](https://raw.githubusercontent.com/marswaveai/ColaMD/main/README.md) 与 GitHub compare 页，全部为 release notes / commit 列表直接支撑的事实，推测处已标注。

## 2. 主界面结构对比

**ColaMD 2.4 的答案**：无工具栏、无状态栏、无永久侧边栏；标签条 + 可拖宽文件面板（180–420px）；未保存 = 标签圆点；**没有最近文件侧边栏**——最近 10 篇放「文件」菜单，主界面只保留文件面板（当前目录）+ 大纲。

**LyraMD 现状**：侧边栏四个 tab（草稿 / 工作目录 / 置顶 / 最近文件）+ 右侧大纲抽屉 + 多窗口；每窗口单文档，打开文件默认新窗口或替换当前。

核心差异：ColaMD 用「标签 = 文档集合」取代了「最近文件列表」的导航职能；面板只管当前目录浏览。这正是她说「有了标签页，最近侧边栏就不再需要」的依据。

## 3. 竞品功能采纳优先级

### P0（下一版就做，决定主界面骨架）
1. **标签页阶段一（opt-in）**：见 §4 方案。
2. **最近文件从侧边栏降级到文件菜单**：`recentFiles` 持久化已有，只需菜单区块 + 侧边栏去 tab；标签页阶段二落地时执行。

### P1（发版后紧跟，低成本高感知）
3. **未保存状态表达收敛**：内部脏状态用圆点/小点，外部修改提示保留文字（我们已有 agent-change 面板，文字侧已对）。
4. **面板几何契约**：侧边栏/大纲宽度设上下限、面板边缘与正文右边界同一条线、正文列在剩余空间居中回流。
5. **`$$` 货币误判排查**：ColaMD #93 修的是「写价格 `$$100` 被当 LaTeX」；我们已上 KaTeX，需确认是否有同样误判。
6. **撤销不跨文档**：我们多窗口已是独立 Milkdown 实例，需确认；做标签页时这是硬门槛。

### P2（排期但不急）
7. 脚注悬停预览；8. 标题锚点跳转；9. 查找**替换**（我们已有浮动搜索，确认是否含替换）；10. 界面语言切换；11. Mermaid 亮度感知配色（我们已有 mermaid sandbox，补深色主题适配即可）；12. 增量更新（blockmap，发版通道成熟后做）。

### 不抄
- 启发式 agent 活动圆点：ColaMD 自己在 v2.0.4 移除了；我们的 agent 状态灯是显式信号链，保留。
- 五天十版的迭代节奏：见 §6 反向教训。

## 4. 标签页方案（两阶段）

**阶段一（opt-in，对应 ColaMD v2.1.0）**
- 设置里加开关「在新标签页中打开文件」（默认关）；开启后 ⌘T 新建 tab、文件列表 ⌘-点击在新 tab 打开、菜单项「在新标签页打开」。
- 单文档时完全不显示标签条——首屏保持简单（她 2026-09-14 定的约束）。
- 每个 tab 独立：内容、撤销历史、未保存状态、滚动位置、draftId/filePath 绑定。

**阶段二（常驻，对应 v2.2.0/2.3.0，阶段一稳定一版后）**
- 标签条常驻，单文档也是一个 tab；打开文件落在 tab 而不是新窗口；启动即「未命名」tab，去欢迎页。
- 此时执行「最近文件挪文件菜单」+ 侧边栏重构（§5）。

**上线门槛（每条都是 Gate，不通过不发布）**——这是 ColaMD 9/13 一天连修 6 条的地方：
- 切换 tab 不得误标文档为已编辑；
- 绝不把 A 文档内容存进 B 的文件路径（现有 `lastSyncedContent` / watcher / `ignoredWatchedContents` 是按 WindowState 绑定的，标签化后必须按 tab 状态隔离）；
- 撤销历史不跨文档；
- autosave 排队期间落盘的编辑不被 tab 切换覆盖；
- 外部变更守卫（`blockedDestructiveApply`）按 tab 各自生效，被拦面板归属正确的 tab；
- 文稿安全链（revision / recovery / journal）记录的 docPath 与活动 tab 一致。

**验收方式**：before/after 截图对照 + 针对上述 6 条门槛逐一写回归测试，一次性做完再发（§6 教训）。

## 5. 侧边栏重构方案

现状问题：四个 tab 职能重叠（草稿/最近/置顶都是「找文稿」），工作目录是唯一不可替代的。

**阶段二标签页常驻后**，侧边栏收敛为两个区：
1. **工作目录**（保留现有树形浏览，补文件夹就地展开——ColaMD v2.3.0 已验证体验更好）；
2. **草稿库**（草稿 + 置顶合并：置顶以星标标记出现在草稿列表顶部，不再是独立 tab）；
3. 最近文件 → 文件菜单（阶段二）；在此之前保留原样，不两次折腾。

配合 §4-P1-4 的几何契约一起做：宽度上下限、分割线与正文同一条线、正文居中回流。

## 6. 反向教训

ColaMD 五天发了 10 个版本，其中 v2.0.5、v2.0.6、v2.1.1、v2.1.2 基本都是在为上一版 UI 擦屁股——顶栏/标签类改动的回归成本被明显低估。LyraMD 的对应纪律：**主界面类改动一次做完、六条门槛全过、截图对照验收，然后才发版**；不拆成「先发再补」。
