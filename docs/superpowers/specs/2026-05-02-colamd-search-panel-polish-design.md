# 2026-05-02 — ColaMD 搜索面板补强设计

## 摘要

本轮设计只补强已经上线的文档内搜索体验，不重做搜索系统，也不扩大到跨文件或替换能力。

目标只收敛为三件事：

1. 搜索面板在视觉上成为真正的右上角悬浮面板，不随正文滚动漂移
2. `Enter / Shift+Enter` 在搜索框内可以稳定跳转上一条与下一条命中
3. 在搜索框中补充当前命中的三行上下文预览，帮助用户判断是否是目标位置

这是一轮搜索体验打磨，不是新一轮功能扩面。所有设计都要服从 ColaMD 的极简原则。

---

## 1. 设计目标

### 1.1 修正“像悬浮但不够悬浮”的观感

当前搜索框虽然位于右上角，但仍更像是挂在编辑器容器里的局部元素。用户滚动正文时，它需要始终保持稳定的右上角悬浮感，不能让人误以为它属于正文流的一部分。

### 1.2 统一搜索跳转入口

当前按钮跳转与键盘跳转存在割裂，用户已经明确反馈 `Enter` 无法正常完成“跳到下一条”的核心动作。

本轮必须把以下入口统一到同一套跳转逻辑：

1. `Enter`：下一条
2. `Shift+Enter`：上一条
3. `上一个 / 下一个` 按钮

### 1.3 降低命中判断成本

只显示 `N / M` 对快速检索还不够。用户需要在不频繁扫回正文的前提下，先在搜索面板里看到当前命中的局部上下文，再决定是否继续跳转。

因此本轮加入固定三行上下文预览：

1. 上一行
2. 当前命中行
3. 下一行

### 1.4 保持范围克制

本轮明确不做：

1. `Cmd/Ctrl+G` 或额外跳转快捷键
2. 替换
3. 正则、整词、大小写开关
4. 结果列表
5. 跨文件搜索

---

## 2. 当前问题与根因假设

### 2.1 悬浮感不足

现有搜索面板挂在 `#editor-shell` 内部，使用局部定位，视觉上仍偏“容器内角标”，而不是“浮在编辑器之上”的面板。

### 2.2 键盘跳转行为不可靠

虽然代码已经尝试监听搜索框内的 `Enter / Shift+Enter`，但用户实际反馈该路径不可用，说明当前搜索输入、IME 组合态、焦点管理或跳转刷新之间仍存在断点。

### 2.3 命中判断依赖正文来回确认

当前只有输入框、计数和上下按钮。用户看见 `3 / 8` 时，仍需要回到正文里找“这一条到底是不是我要的”。这会让搜索变成频繁试错，而不是快速定位。

---

## 3. 方案对比与结论

### 3.1 方案 A：最小补丁式修复

做法：

1. 保留当前 DOM 结构
2. 只修 `Enter / Shift+Enter`
3. 上下文预览用最简单的文本块插入

优点：

1. 改动最小
2. 风险最低

缺点：

1. 悬浮观感提升有限
2. UI 结构会继续向临时补丁累积

### 3.2 方案 B：固定悬浮面板 + 三行上下文 + 统一跳转逻辑

做法：

1. 保持搜索面板仍为轻量悬浮卡片
2. 调整定位方式与层级，让它在视觉上固定于编辑器右上角
3. 在输入区与按钮区之间增加三行上下文预览
4. 按钮和键盘全部复用同一套 next / prev 逻辑

优点：

1. 最符合用户当前诉求
2. 结构仍然轻，不会把搜索面板做成重型浮层
3. 实现成本与产品收益的比例最好

缺点：

1. 需要稍微重整面板 DOM 与状态刷新逻辑
2. 需要补 UI 与键盘回归测试

### 3.3 方案 C：扩成完整搜索浮层

做法：

1. 把搜索框继续扩成更完整的浮层
2. 同时引入更多结果、筛选或高级选项

优点：

1. 扩展空间大

缺点：

1. 超出本轮需求
2. 容易违背极简边界

### 3.4 结论

本轮采用 **方案 B：固定悬浮面板 + 三行上下文 + 统一跳转逻辑**。

原因：

1. 它完整覆盖用户当前提出的三个核心问题
2. 它不会让现有轻量搜索面板失去极简特征
3. 它能在不扩面的前提下，明显提升“搜索是否可用”的体感

## 4. 交互设计

### 4.1 打开与关闭

1. `Cmd/Ctrl+F` 打开搜索面板并聚焦搜索框
2. 如果存在选中文本，优先将选中文本填入搜索框
3. `Escape` 关闭搜索面板并把焦点还给编辑器
4. 面板关闭时不清空当前文档的搜索记忆

当面板已经处于打开状态时，再次按 `Cmd/Ctrl+F` 的行为固定为：

1. 重新聚焦搜索输入框
2. 全选当前输入内容
3. 如果正文里存在新的非空选中文本，则用新选区覆盖当前 query
4. 如果没有新的非空选中文本，则保留当前 query 不变

### 4.2 跳转行为

1. `Enter`：跳到下一条命中
2. `Shift+Enter`：跳到上一条命中
3. 点击 `下一个`：跳到下一条命中
4. 点击 `上一个`：跳到上一条命中

以上四个入口必须调用同一套跳转逻辑，不允许按钮行为和键盘行为分叉。

### 4.2.1 首次激活规则

当搜索面板首次打开，或 query 发生变化并触发结果重算时，当前 active match 按以下确定性规则选定：

1. 如果当前编辑器选区刚好就是某一条完整命中，则优先激活该命中
2. 否则，激活当前位置之后的第一条命中
3. 如果当前位置之后没有命中，则回环激活第一条命中
4. 如果没有任何命中，则 `activeIndex = -1`

因此，首次显示的 `N / M`、三行上下文，以及第一次按下 `Enter` 后的跳转行为，都以这条 active 选择规则为准。

### 4.3 结果计数

面板顶部继续显示 `当前序号 / 总命中数`：

1. 无 query：`0 / 0`
2. 有 query 但无结果：`0 / 0`
3. 命中存在：如 `3 / 8`

### 4.4 三行上下文预览

搜索输入行下方新增一个固定区域，展示当前命中的三行上下文：

1. 上一行
2. 当前命中行
3. 下一行

这里的“行”明确定义为 **搜索文本索引里的换行分隔文本行**：它来自编辑器当前文档内容生成的一份纯文本索引，由各个文本块按顺序串联，并以 `\n` 分隔。它不是视觉换行后的显示行，也不是按原始 `.md` 文件字节级逐行回放。

其中当前命中行需要将当前 active match 做出明显高亮，以便用户在面板内直接确认位置。面板只强调当前 active match，不额外高亮该行里其他同 query 命中。

### 4.4.1 多行 query 边界

本轮搜索面板只支持 **单行 query**。

1. 搜索输入框中的换行输入不作为正式支持范围
2. 如果 query 来自跨行选区、粘贴文本或其他来源并包含换行，则在进入搜索状态前先将连续换行规范化为单个空格
3. 规范化后的 query 继续参与计数、命中与预览构造
4. 因此本轮不存在“一个 active match 横跨多行预览区”的渲染要求，三行上下文始终围绕单一当前行展示

### 4.5 空态与边界态

1. 无 query：上下文区显示引导态，例如“输入关键词开始搜索”
2. 有 query 但无结果：上下文区显示“未找到匹配内容”
3. 命中位于文档首行：上一行显示为空态占位
4. 命中位于文档末行：下一行显示为空态占位
5. 只有一条命中：`Enter` 与 `Shift+Enter` 可回环到同一条，行为保持一致

### 4.6 滚动与稳定性

1. 用户滚动正文时，搜索面板视觉位置保持稳定
2. 搜索跳转导致正文滚动时，面板不闪烁、不重排、不暂时消失
3. 编辑器内容刷新后，若搜索面板仍打开，则计数与上下文需按当前搜索状态刷新

## 5. 视觉与布局设计

### 5.1 面板结构

搜索面板从上到下分为三层：

1. 输入层：输入框、命中计数、关闭按钮
2. 预览层：三行上下文
3. 操作层：`上一个 / 下一个`

### 5.2 悬浮方式

面板应表现为编辑器上方的轻量悬浮卡片：

1. 锚定于编辑器可视区域的右上角，而不是整个窗口 viewport，也不是正文内容流
2. 不参与正文排版
3. 用户滚动正文时，面板相对编辑器可视区域保持原位
4. 保持比正文略高的层级，但不抢系统设置弹窗这类更高优先级浮层

### 5.3 预览样式

1. 三行上下文的字体和间距要明显低于正文主内容层级
2. 当前命中行比上下两行更突出
3. 命中词高亮要与正文中的搜索高亮风格相呼应，但不必完全一致
4. 空态占位应尽量轻，不制造额外视觉噪声

## 6. 技术结构设计

### 6.1 复用现有搜索状态源

本轮不推翻已经接入的编辑器内搜索状态，而是在其基础上增强搜索面板消费层。

预期结构：

1. 编辑器层继续维护 query、命中列表、active match、next / prev 跳转
2. renderer 层负责面板展示、快捷键事件、上下文渲染

### 6.2 上下文数据来源

已有搜索 helper 中保留了 match preview 能力，本轮优先复用现有预览模型，而不是重新发明一套上下文切片逻辑。数据来源要明确为“编辑器当前搜索状态里的 active preview”，而不是 renderer 自己再次扫描全文。

本轮上下文预览的权威文本源固定为：

1. 编辑器层根据当前 ProseMirror 文档生成的纯文本搜索索引
2. 该索引按文本块顺序拼接，并用 `\n` 作为行分隔
3. `buildSearchMatchPreview` 及同类 preview 构造逻辑都以这份索引文本为输入

换句话说，renderer 展示的三行上下文，消费的是“当前编辑器文档的搜索文本索引预览”，而不是原始 Markdown 文件内容逐行切片，也不是视觉渲染后的屏幕行。

需要暴露或消费的数据最少包括：

1. 当前 active match
2. `previousLine`
3. `before`
4. `match`
5. `after`
6. `nextLine`

建议边界如下：

1. `src/renderer/editor/search.ts` 继续作为 preview 数据模型的最小定义来源
2. 编辑器层对外暴露“当前搜索状态快照”，其中包含 `query`、`totalMatches`、`activeIndex` 和 `active preview`
3. renderer 层不重新计算 preview，只把状态快照渲染成三行预览

renderer 层将这些字段渲染成三行预览，其中“当前行”由 `before + match + after` 组成。

如果存在命中但某一条 preview 因 offsets 无法映射或字段缺失而构造失败，降级规则为：

1. 不让 renderer 自行猜测上下文文本
2. 该条 preview 显示为轻量占位态，例如“当前匹配已定位，预览暂不可用”
3. 命中跳转与计数仍保持可用

### 6.3 跳转逻辑收口

本轮要把所有“上一条 / 下一条”入口收口到统一调用路径，避免未来再次出现：

1. 按钮能跳
2. `Enter` 不能跳
3. 状态刷新不同步

### 6.4 IME 与焦点安全

中文输入场景必须保持 composition-safe：

1. 组合输入期间不把 `Enter` 误判为跳转
2. 关闭搜索后恢复编辑器焦点
3. 按钮跳转后保持可继续编辑或继续搜索的稳定焦点策略

更具体地说：

1. `compositionstart` 到 `compositionend` 期间，`Enter` 与 `Shift+Enter` 都只服务输入法提交，不触发搜索跳转
2. 只有在非 composition 态下，`Enter` 才会被解释为下一条，`Shift+Enter` 才会被解释为上一条
3. 空 query 或无结果时，`Enter` / `Shift+Enter` 为 no-op，但不关闭面板、不清空输入
4. 无论触发入口是按钮还是 `Enter / Shift+Enter`，跳转完成后焦点都继续留在搜索输入框，便于连续搜索
5. 只有 `Escape` 关闭面板时，焦点才回到编辑器
6. 点击 `上一个 / 下一个` 按钮本身不应导致搜索输入框失焦

### 6.5 最小状态流转

为避免 renderer 与编辑器层状态分叉，本轮把最小状态流转定为：

1. 打开搜索面板：
   编辑器层读取当前选中文本或当前文档记忆 query，生成最新搜索状态；renderer 只显示这份状态
2. 输入 query：
   renderer 把新 query 交给编辑器层；编辑器层基于最新文档文本重新计算 `results`、`activeMatch` 与 `preview`
3. 跳转上一条 / 下一条：
   编辑器层只更新 `activeIndex` 和对应 `active preview`；renderer 重新渲染计数与三行上下文
4. 关闭搜索面板：
   renderer 隐藏面板，编辑器层保留当前文档的临时 query 记忆

其中 `preview` 永远从当前 `activeMatch` 派生，renderer 不单独缓存一份可变 preview 状态。

### 6.6 文档内容变化时的重算规则

当正文内容变化时，不论变化来自用户编辑还是外部热更新，都按同一规则处理：

1. 保留当前 `query`
2. 基于最新文档文本重新计算全部 matches
3. 如果旧的 active match 在新结果中仍然存在，则继续保留该 active match
4. 如果旧的 active match 已失效但仍有结果，则优先取更新后位置不晚于原 active match 的最近后继命中
5. 如果不存在后继命中，则取最近前驱命中
6. 如果新结果为空，则 `activeIndex` 设为 `-1`，计数显示 `0 / 0`，上下文显示“未找到匹配内容”

这样 implementation plan 可以明确把“内容刷新后的搜索状态”视为一次确定性的重算，而不是依赖旧光标位置做模糊推断。正文热更新后只保证按新结果集重算，不保证锚定到语义上同一处内容。

## 7. 验收标准

### 7.1 用户可见行为验收

以下行为全部成立，才算本轮完成：

1. `Cmd/Ctrl+F` 能打开搜索面板并聚焦输入框
2. 面板在正文上下滚动时仍稳定悬浮于右上角
3. 输入关键词后，`Enter` 跳下一条
4. `Shift+Enter` 跳上一条
5. `上一个 / 下一个` 与键盘跳转行为一致
6. 面板显示 `上一行 / 当前命中行 / 下一行`
7. 当前命中行中的关键词有可辨识高亮
8. 无 query 与无结果时，面板有合理空态
9. 点击 `上一个 / 下一个` 后，搜索输入框仍保持焦点

### 7.2 自动化验证

至少覆盖以下几类测试：

1. 搜索状态与跳转逻辑测试
2. 三行上下文预览构造测试
3. 空结果、首行、末行、单结果回环测试
4. 搜索面板键盘事件回归测试
5. 热更新后 active match 回退规则测试

### 7.3 人工回归重点

实现完成后需要重点手测：

1. 中文输入法组合输入
2. 长文档连续 `Enter` 跳转
3. 搜索面板打开状态下滚动正文
4. 搜索跳转与正文选区恢复

---

## 8. 不在本轮范围内

以下能力明确延后，不作为本轮验收项：

1. 搜索结果列表
2. 搜索历史
3. `Cmd/Ctrl+G` 等额外快捷键
4. 替换
5. 大小写、整词、正则开关
6. 跨文件或工作区搜索

---

## 9. 实施建议

实现时建议拆成两个独立切片，各自验证并单独提交：

1. 搜索面板定位与键盘跳转修复
2. 三行上下文预览与空态渲染

这样可以把“核心可用性修复”和“信息密度增强”分开落地，降低回归面。
