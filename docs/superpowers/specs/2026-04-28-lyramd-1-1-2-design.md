# 2026-04-28 — LyraMD 1.1.2 编辑体验设计

## 摘要

在 `0.1.1` 稳定基线上重整四条关键链路：

1. 文件身份模型：正式文件、原始空白文档、草稿文件
2. 保存链路：自动保存、切换前 flush、草稿恢复
3. 搜索链路：当前文件搜索 + 可扩展搜索面板骨架
4. 响应式链路：窄窗口下的覆盖式抽屉侧边栏

本设计明确拒绝直接沿用 `1.0.1` 的整体实现，只吸收少量方向，例如标题栏局部化交互和更轻的视觉目标。

---

## 1. 设计原则

### 1.1 如非必要，勿增实体

- 不新增工具栏、状态栏、复杂设置页
- 搜索面板仅在需要时出现
- onboarding 只负责草稿目录选择，不演变成多页欢迎流程

### 1.2 不让未保存内容悬空

- 只要用户开始编辑，内容就必须进入可恢复路径
- “未命名”不再等于“脆弱内存态”
- 只有完全未编辑的空白文档可以保持不落盘

### 1.3 结构要为未来扩展留口

- 当前版本只做当前文件搜索
- 但搜索 UI、状态模型和结果容器都要兼容未来切到最近文件/工作目录

### 1.4 小窗口先保正文

- 响应式设计优先保护正文可写区域
- 侧边栏在窄窗口下退为抽屉，不与正文硬拼宽度

---

## 2. 信息架构

### 2.1 主界面

主界面继续维持两层结构：

- 标题栏
- 编辑区

标题栏内新增或调整以下能力：

- 左侧侧边栏开关按钮：`竖栏 + 面板`
- 搜索激活后，右上角显示浮动搜索面板
- 其余能力尽量不显式占位

### 2.2 侧边栏结构

从上到下固定为：

1. `当前`
2. `草稿`
3. `最近`
4. `工作目录`

#### 当前

- 展示当前正在编辑的文档
- 若是空白未编辑文档，显示未命名状态

#### 草稿

- 只展示真实草稿文件
- 不展示空白未编辑文档
- 支持切换、恢复和后续扩展更多管理操作

#### 最近

- 只展示正式文件
- 不混入草稿

#### 工作目录

- 延续已有工作目录模式
- 仍然用于固定目录下的 Markdown 导航

---

## 3. 文档身份模型

### 3.1 三种文档身份

建议将当前窗口内文档状态划分为三类：

1. **正式文件**
   - 已有真实路径
   - 来自用户打开、最近文件、工作目录，或草稿转正

2. **原始空白文档**
   - 通过 `Cmd/Ctrl+N` 创建
   - 用户尚未编辑
   - 不落盘，不进入草稿区

3. **草稿文件**
   - 原始空白文档在用户第一次真实编辑后晋升而来
   - 已有真实路径，位于草稿目录
   - 支持自动保存、恢复和切换

### 3.2 状态迁移

```text
Cmd/Ctrl+N
  -> 原始空白文档
  -> 用户开始编辑
  -> 创建草稿文件
  -> 自动保存
  -> Save As
  -> 转为正式文件
```

边界规则：

- 原始空白文档若未编辑，关闭或切换时直接丢弃
- 原始空白文档一旦编辑，必须立刻进入草稿托管
- 草稿转正后，从草稿区移除，进入最近文件

---

## 4. 草稿设计

### 4.1 草稿目录

目录来源优先级：

1. 用户在 onboarding 中明确选择的目录
2. 用户跳过时的默认目录：`Documents/LyraMD Drafts`

### 4.2 onboarding

- 首次启动显示轻量引导
- 只做一件事：说明草稿机制并允许选择目录
- 用户可跳过
- 跳过后直接采用默认目录

### 4.3 草稿命名

建议文件系统命名使用稳定唯一 id，例如：

- `draft-20260428-103122-1.md`
- 或 UUID 风格命名

UI 展示名不直接暴露底层文件名，优先级如下：

1. 一级标题
2. 第一行非空内容
3. `未命名草稿`

### 4.4 恢复策略

- 启动时自动恢复上次活动草稿
- 侧边栏草稿区始终保留其他草稿的手动恢复入口

### 4.5 草稿转正

当用户执行保存到自定义位置时：

1. 打开 `Save As`
2. 用户选择正式路径
3. 当前文档切换为正式文件身份
4. 原草稿从草稿索引和草稿区移除
5. 正式文件写入最近文件

这里是身份迁移，不是“另存一份副本后保留旧草稿”。

---

## 5. 保存与切换设计

### 5.1 自动保存

适用对象：

- 正式文件
- 草稿文件

不适用对象：

- 原始空白文档

### 5.2 自动保存触发

- 用户真实编辑后进入去抖保存
- 程序性更新（例如外部文件刷新）不能触发自动保存

### 5.3 切换前 flush

以下操作都必须先 flush 当前文档：

- 打开最近文件
- 打开工作目录文件
- 打开草稿
- `Cmd/Ctrl+N`

如果当前是原始空白文档且未编辑，则无需 flush。

### 5.4 外部文件热更新

已有文件监听逻辑需要继续保留，但必须显式区分：

- 用户编辑
- 程序性 `setMarkdown`
- 外部文件 watcher 写回

防止出现：

- 外部更新被误判成用户编辑并触发自动保存
- 自动保存覆盖外部 Agent 刚写入的内容

---

## 6. 搜索设计

### 6.1 UI 形态

- 位置：编辑器右上角浮动面板
- 打开方式：`Cmd/Ctrl+F`
- 默认聚焦输入框
- 关闭后不保留常驻占位

### 6.2 当前版本范围

- 只搜索当前文件

### 6.3 交互形态

采用混合型结果模型：

- 默认展示当前命中卡片
  - 当前第几条
  - 前后文摘要
- 提供上下跳转
- 命中较多时可展开结果列表

### 6.4 未来扩展位

虽然当前版本不接入多源搜索，但面板结构要允许未来增加：

- 搜索范围切换器
  - 当前文件
  - 最近文件
  - 工作目录

为避免未来重做，当前实现建议把“数据源”和“面板 UI”分层。

### 6.5 焦点规则

- `Cmd/Ctrl+F`：聚焦搜索面板
- `Cmd/Ctrl+L`：无论当前是否刚搜索过，都回到正文上次编辑位置

---

## 7. 响应式与侧边栏设计

### 7.1 宽窗口模式

- 侧边栏按现有占位布局显示
- 正文区域跟随剩余宽度

### 7.2 窄窗口模式

当窗口宽度低于阈值时：

- 侧边栏自动切为覆盖式抽屉
- 默认关闭
- 正文占满可用宽度

### 7.3 抽屉交互

- 点击标题栏按钮：从左侧滑出
- 再次点击按钮：收回
- 点击正文空白处：收回

本版本不做：

- 左边缘热点
- 触控板式系统手势

### 7.4 视觉更新

- 侧边栏按钮图形采用 `竖栏 + 面板`
- 应用图标替换为用户提供的新稿

---

## 8. 进程职责与模块边界

### 8.1 主进程

建议在 `src/main/index.ts` 侧负责：

- 当前窗口文档身份状态
- 草稿目录配置读取与持久化
- onboarding 所需目录选择
- 草稿创建、恢复、转正
- 自动保存和切换前 flush 协调
- 响应式阈值判定所需的窗口级状态
- 最近文件与草稿区分流

### 8.2 preload

建议在 `src/preload/index.ts` 暴露最小 IPC：

- 草稿目录与 onboarding 状态读取
- 草稿列表读取和切换
- 搜索面板命令
- 响应式侧边栏模式变化事件

### 8.3 渲染进程

建议在 `src/renderer/main.ts` / `editor.ts` / `base.css` 负责：

- 侧边栏顺序和草稿区渲染
- 搜索面板 UI 和结果展示
- `Cmd/Ctrl+F` / `Cmd/Ctrl+L`
- 抽屉动画和遮罩交互
- 标题栏按钮视觉更新

---

## 9. 持久化状态建议

除现有侧边栏状态外，建议新增如下持久化字段：

- `draftDirectoryPath`
- `draftOnboardingCompleted`
- `lastActiveDocument`
- `draftEntries`

`draftEntries` 最低需要：

- 草稿路径
- 创建时间
- 最近修改时间
- 最近是否活动

`lastActiveDocument` 需要能区分：

- 正式文件
- 草稿文件
- 原始空白文档（通常无需恢复）

---

## 10. 风险点

### 10.1 自动保存与热更新竞争

需要防止用户自动保存与外部 watcher 更新互相覆盖。

### 10.2 草稿身份迁移

`Save As` 后不能同时保留草稿和正式文件双影子。

### 10.3 搜索高亮实现

需要确认 Milkdown / ProseMirror 当前扩展方式下，高亮不会破坏编辑和撤销体验。

### 10.4 抽屉模式交互

要验证遮罩、点击关闭、焦点切换和滚动都正常。

---

## 11. 验证策略

### 自动测试

- 主进程草稿状态机
- 最近文件与草稿分流
- 草稿转正逻辑
- 侧边栏持久化状态

### 人工验收

- 编辑已有文件后切换，不丢记录
- 新建空白文档但不编辑，不生成草稿
- 新建并编辑后生成草稿，重启可恢复
- 搜索面板可用，命中上下文清晰
- `Cmd/Ctrl+L` 回到正文
- 缩窄窗口后抽屉侧边栏可正常呼出

---

## 12. 结论

`1.1.2` 的本质不是“再做几个功能”，而是把 LyraMD 的编辑底座补齐：文档身份清晰、内容不再悬空、搜索开始有统一入口、响应式行为终于可控。只要这版做稳，后续无论扩展搜索范围，还是继续打磨 Agent 协作体验，都会顺很多。
