# LyraMD 1.1.2 需求文档

- **日期**：2026-04-28
- **状态**：已确认，可进入设计实现
- **版本定位**：`0.1.1` 稳定基线上的编辑体验重整版

## 1. 背景

LyraMD 当前已经从原始 ColaMD 演化为面向个人 Agent 协作工作流的 Markdown 编辑器。`0.1.1` 是当前已验证的稳定基线；`1.0.1` 曾尝试加入自动保存、局部缩放和当前窗口新建等能力，但整体实现质量未被采纳。

`1.1.2` 的目标不是继续堆功能，而是把以下几条最关键的编辑体验链路修顺：

- 不再因切换文件丢失编辑记录
- 未命名文档进入可恢复的草稿体系
- 搜索能力从零建立，但为未来全局搜索预留结构
- 小窗口下仍可用，侧边栏不再挤坏正文
- 标题栏和应用图标回到更干净的产品气质

## 2. 版本目标

### 核心目标

1. 文件切换和窗口关闭后，不再丢失用户刚刚编辑的内容
2. 未命名文档具备真实的草稿托管和恢复能力
3. 提供当前文件搜索能力，并为未来扩展到最近文件/工作目录搜索留好骨架
4. 支持更自由的窗口缩放，小窗口下以正文优先
5. 保持 LyraMD 极简气质，不引入工具栏、状态栏和重型设置界面

### 成功标准

- 用户编辑已有路径文件后，切换到其他文件时不丢内容
- 用户编辑未命名文档后，重启应用仍能找回草稿
- 搜索可通过 `Cmd/Ctrl+F` 打开，支持上下跳转并显示上下文
- 窗口缩窄时，侧边栏自动切为覆盖式抽屉
- 侧边栏结构和视觉风格更清晰，不让草稿和最近文件混在一起

## 3. 范围

### 本版本包含

1. 当前文件搜索
2. 已有路径文件自动保存
3. 草稿目录 onboarding
4. 多草稿模型
5. 草稿区侧边栏
6. `Cmd/Ctrl+L` 回到正文
7. 更自由的小窗口行为
8. 覆盖式抽屉侧边栏
9. 侧边栏按钮图形更新
10. 应用图标更新

### 本版本不包含

1. 搜索替换
2. 最近文件/工作目录全文搜索的真实数据接入
3. 快捷键设置界面
4. 草稿管理设置页
5. 边缘热点呼出或系统级手势
6. 文件管理器式的工作区功能

## 4. 已确认产品决策

### 4.1 版本基线

- `1.1.2` 基于 `0.1.1`
- `1.0.1` 只允许选择性吸收个别方向，不继承整体实现

### 4.2 侧边栏结构

侧边栏从上到下固定为：

1. `当前`
2. `草稿`
3. `最近`
4. `工作目录`

其中 `草稿` 是新增独立区域，不能与 `最近` 混排。

### 4.3 搜索

- 入口：编辑器右上角浮动搜索面板
- 快捷键：`Cmd/Ctrl+F`
- 当前版本范围：仅搜索当前文件
- 结果形态：默认轻量面板，但展示当前命中的上下文
- 扩展方向：后续可扩成 `当前文件 / 最近文件 / 工作目录`
- 结果交互：采用混合型，默认轻量，必要时可展开为结果列表

### 4.4 自动保存与切换

- 已有路径文件：用户编辑后自动保存
- 切换到其他文件前：若有未落盘变更，先自动 flush
- 切换来源统一适用于：
  - 草稿
  - 最近
  - 工作目录

### 4.5 草稿体系

- 首次启动弹轻量 onboarding
- 用户可跳过 onboarding
- 跳过后默认草稿目录：`Documents/LyraMD Drafts`
- 未命名文档在用户开始编辑后才晋升为真实草稿文件
- 如果新建后未编辑，仍是原始空白文档，不落盘、不进入草稿区
- 采用多草稿模型，每次真正编辑一个未命名文档时生成独立草稿
- 草稿需要支持：
  - 自动保存
  - 启动自动恢复
  - 侧边栏手动找回

### 4.6 草稿与正式文件分流

- 草稿不进入 `最近`
- 草稿统一进入 `草稿` 区
- 正式文件才进入 `最近`
- 草稿执行 `Save As` 后，身份迁移为正式文件：
  - 当前编辑上下文切到正式文件
  - 原草稿从草稿区移除
  - 正式文件进入最近文件

### 4.7 快捷键

- `Cmd/Ctrl+F`：打开并聚焦搜索面板
- `Cmd/Ctrl+L`：永远回到正文编辑区，并回到上次编辑位置
- 侧边栏快捷键延续现有开关逻辑，不单独新增设置页

### 4.8 小窗口行为

- 正常宽度：侧边栏为占位布局
- 窄窗口：侧边栏自动切为覆盖式抽屉
- 抽屉默认关闭，正文优先
- 呼出方式：只做按钮呼出 + 左侧滑出动画
- 本版本不做边缘热点和系统级手势

### 4.9 视觉更新

- 侧边栏按钮采用 `竖栏 + 面板` 图形方向
- 应用图标替换为用户提供的新稿

## 5. 典型用户流程

### 流程 A：编辑已有文件并切换

1. 用户打开已有 Markdown 文件
2. 在正文中编辑内容
3. 用户切换到最近文件或工作目录中的另一个文件
4. 当前文件自动保存
5. 目标文件打开
6. 用户返回时，原文件内容已经正确写盘

### 流程 B：创建并恢复草稿

1. 用户按 `Cmd/Ctrl+N`
2. 出现原始空白文档
3. 用户开始输入
4. 文档晋升为真实草稿，自动进入草稿区
5. 用户关闭应用
6. 下次启动时自动恢复上次草稿
7. 用户也可从草稿区手动切回其他草稿

### 流程 C：搜索当前文件

1. 用户按 `Cmd/Ctrl+F`
2. 右上角搜索面板打开并聚焦
3. 输入关键字
4. 面板显示当前命中与上下文
5. 用户用上下按钮在命中间跳转
6. 命中较多时可展开结果列表

### 流程 D：小窗口下使用侧边栏

1. 用户将窗口缩窄到阈值以下
2. 侧边栏自动切换为覆盖式抽屉模式
3. 默认收起，正文占满主区域
4. 用户点击标题栏按钮
5. 侧边栏从左侧滑出
6. 用户点正文或再次点按钮关闭抽屉

## 6. 验收标准

- [ ] 已有路径文件编辑后会自动保存
- [ ] 从当前文件切到草稿/最近/工作目录时不丢记录
- [ ] 新建但未编辑的空白文档不会生成草稿文件
- [ ] 新建并开始编辑后，会生成独立草稿文件
- [ ] 重启应用后，能自动恢复上次活动草稿
- [ ] 侧边栏中清晰显示 `当前 / 草稿 / 最近 / 工作目录`
- [ ] `Cmd/Ctrl+F` 能打开浮动搜索面板
- [ ] 搜索面板能显示命中上下文并支持上下跳转
- [ ] `Cmd/Ctrl+L` 能把焦点带回正文上次编辑位置
- [ ] 窗口缩窄后，侧边栏变成覆盖式抽屉并可正常呼出
- [ ] 侧边栏按钮更新为更简洁的图形
- [ ] 应用图标更新为新稿

## 7. 风险与注意事项

- 自动保存不能和外部文件热更新互相打架
- 草稿身份迁移不能在侧边栏里留下重复影子
- 搜索高亮不能破坏 Milkdown 的编辑体验
- 抽屉模式不能导致点击穿透、焦点丢失或滚动异常

## 8. 结论

`1.1.2` 是一次“编辑体验基础设施”整理，而不是简单功能叠加。它要解决的核心问题是：让 LyraMD 成为一个可以放心一直开着写、切、找、缩放的 Agent Native Markdown 编辑器。
