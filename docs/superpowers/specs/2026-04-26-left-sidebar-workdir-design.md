# ColaMD 左侧侧边栏与工作目录设计

- **日期**：2026-04-26
- **状态**：已确认，可进入实现计划
- **范围**：v1

## 背景

ColaMD 当前窗口结构极简，只有标题栏和编辑器。用户希望增加一个可收起的左侧侧边栏，用于：

- 查看当前文件
- 查看最近打开文件
- 固定一个长期可见的工作目录
- 在工作目录中切换 Markdown 文件

这个能力需要保留 ColaMD 的极简气质，避免产品快速滑向完整文件管理器。

## 核心决策

### 1. 入口位置

在 macOS 标题栏左上角红黄绿窗口按钮右侧，增加一个 Claude 风格的侧边栏开关按钮。

- 该按钮属于标题栏，不属于正文工具栏
- 默认存在感低，hover 时增强可见性
- 点击后展开或收起侧边栏

### 2. 快捷键

增加一个侧边栏开关快捷键：

- `CmdOrCtrl+\`

该快捷键只负责开关侧边栏，不承担其他行为。

### 3. 侧边栏信息结构

侧边栏内保留两个主区域：

1. `当前文件`
2. `最近文件`
3. `工作目录`

其中 `工作目录` 是一个完整区域，不再拆成“固定目录”和“目录文件列表”两个独立块。

`工作目录` 区域包含：

- 区域标题 `工作目录`
- 标题同行右侧的 `更换` 按钮
- 当前工作目录下的 Markdown 文件列表

### 4. 工作目录文件展示方式

工作目录采用以下展示方式：

- 递归扫描工作目录及其子文件夹中的所有 `.md` / `.markdown` / `.mdown` / `.mkd`
- 侧边栏中使用“相对路径平铺列表”展示，不做完整树形目录

示例：

```text
daily/0419-claude-感受.md
product/产品路线.md
rules/写作规则.md
工作台.md
```

选择这个方案的原因：

- 比“只显示文件名”更清楚，能区分子目录来源
- 比完整树形目录更轻，复杂度可控
- 更符合 ColaMD 当前的极简产品定位

### 5. 工作目录持久化

工作目录路径必须持久化保存。

- 用户首次选择工作目录后，应用关闭再打开时仍然保留这个目录
- 除非用户主动点击 `更换` 并选择新目录，否则工作目录不变

### 6. 工作目录可折叠

`工作目录` 区域本身支持折叠/展开。

- 折叠时仅显示标题行和 `更换` 按钮
- 展开时显示工作目录文件列表
- 折叠状态建议同样持久化

### 7. 文件点击行为

从侧边栏点击文件时，在**当前窗口**直接切换打开文件，不新建窗口。

原因：

- 侧边栏的定位是当前窗口内的文档导航
- 如果点击列表项还新开窗口，会削弱“围绕一组文档工作”的体验
- 更符合用户对左侧导航栏的直觉预期

## 用户界面细节

### 标题栏按钮

- 位于红黄绿按钮右侧
- 默认低对比度显示
- hover 时显示轻微背景和边框反馈
- 激活时显示侧边栏已展开状态

### 当前文件

显示当前正在编辑的文件名。

可选补充：

- 小字显示状态说明，例如“当前打开”

### 最近文件

按最近打开时间倒序显示，独立于工作目录存在。

特点：

- 即使文件不在当前工作目录中，只要最近打开过，仍然可以显示在最近文件里
- 如果某个文件同时在最近文件和工作目录中出现，这是允许的，不去重

### 工作目录

UI 上是一个整体区域，而不是两个 section。

结构：

- 左侧标题：`工作目录`
- 右侧按钮：`更换`
- 可折叠的 Markdown 文件列表

目录路径本身不需要单独占一个大块。建议只作为这个区域里的辅助信息存在，例如：

- 标题下方用一行小字显示当前路径
- 或 hover/tooltip 中显示完整路径

目标是尽量保留干净的视觉层次。

## 空状态与异常状态

### 未设置工作目录

当用户还没有选择工作目录时：

- `工作目录` 区域显示空状态
- 提示用户选择一个工作目录
- 点击 `更换` 或空状态按钮后打开目录选择器

### 工作目录存在但无 Markdown 文件

当目录中不存在任何 Markdown 文件时：

- 显示“这个目录里没有 Markdown 文件”

### 工作目录路径失效

当持久化保存的工作目录路径已不存在时：

- 启动时清空该工作目录状态
- `工作目录` 区域回到空状态
- 不应导致应用报错或阻塞启动

### 最近文件失效

当最近文件中的某些路径已不存在时：

- 自动跳过无效项
- 不应在列表中显示失效路径

## 数据模型

建议持久化以下状态：

```ts
interface SidebarState {
  sidebarOpen: boolean
  workdirExpanded: boolean
  workdirPath: string | null
  recentFiles: string[]
}
```

约束：

- `recentFiles` 按最近访问时间倒序
- `recentFiles` 需要去重
- `recentFiles` 建议限制最大长度，例如 `20`

## 进程职责划分

### 主进程负责

- 打开系统目录选择器
- 保存与读取侧边栏相关持久化状态
- 递归扫描工作目录
- 过滤 Markdown 文件
- 根据点击的工作目录文件路径在当前窗口加载文件
- 维护最近文件列表

### preload 负责

- 暴露与侧边栏相关的最小 IPC API 给渲染进程

建议新增的 preload 能力包括：

- 读取侧边栏初始状态
- 切换侧边栏开关状态
- 读取工作目录文件列表
- 选择工作目录
- 订阅工作目录状态变化

### 渲染进程负责

- 渲染侧边栏布局
- 渲染 `当前文件`、`最近文件`、`工作目录`
- 维护展开/收起的即时 UI 状态
- 响应标题栏按钮和快捷键
- 响应点击文件后的高亮更新

## 与现有打开文件逻辑的关系

当前 ColaMD 已支持：

- 菜单 `Open...`
- 拖拽文件打开
- 通过路径在窗口中加载文件

v1 侧边栏需要与这些入口共存：

- 任何通过现有入口打开的文件，都应加入最近文件
- 如果当前打开文件位于工作目录内，则工作目录列表中的对应项高亮
- 如果当前打开文件不在工作目录内，也允许正常编辑，只是不在工作目录列表中高亮

## 测试与验收

### 自动验证建议

- 选择工作目录后，重启应用仍能恢复工作目录
- 工作目录递归扫描可正确列出子目录中的 Markdown 文件
- 最近文件列表可正确去重和排序
- 点击工作目录文件项后，当前窗口正确切换文件
- 工作目录路径失效时，应用能回到空状态

### 人工验收建议

1. 点击标题栏按钮，侧边栏展开/收起正常
2. 使用 `CmdOrCtrl+\`，行为与点击按钮一致
3. 选择一个有多层子目录的工作目录，列表显示为相对路径平铺形式
4. 关闭应用重新打开，工作目录仍然存在
5. 折叠工作目录，再次打开应用，折叠状态保持

## 明确不做

以下能力不进入 v1：

- 完整树形目录展开/折叠
- 上下方向键切换文档
- 多工作目录
- 搜索过滤工作目录文件
- 收藏/置顶文件
- 文件重命名、移动、删除等文件管理功能

## 实现提示

- 当前代码库没有独立的应用壳层，渲染进程目前只有标题栏和编辑器，v1 需要先引入一个基础 shell 布局
- 主进程已有文件打开和路径加载能力，可优先复用现有 `open-file-path` / `loadFileInWindow` 路径，而不是重造打开逻辑
- 递归扫描工作目录时，需避免把列表设计成阻塞式重计算；v1 可接受同步触发后异步返回结果

## 结论

v1 的正确边界是：

- 标题栏按钮 + 单快捷键
- `最近文件`
- 可折叠、可持久化的 `工作目录`
- 递归扫描子目录中的 Markdown 文件
- 用相对路径平铺展示
- 当前窗口内切换文件

这个范围已经足够建立 ColaMD 的“围绕一组文档工作”的体验，但还没有跨到完整文件管理器。
